# Setup Command Implementation Guide

This guide explains how to implement the `/setup` command that gets generated for user workflows.

## Purpose

The `/setup` command is created by `/create-agent` in each user's workflow project. It helps new users (or the original user in a new environment) validate their environment is ready to run the workflow.

## Overview

When a user runs `/setup` in their workflow, check:
1. Git availability
2. Connectors the workflow needs (verified, not installed)
3. File structure
4. Security issues
5. Environment configuration
6. Local permissions configuration

## Implementation Instructions

When a user runs the generated `/setup` command in their workflow, Claude should:

### 1. Git Status
```bash
git --version
```

If git not available:
- Explain why git is needed (version control, collaboration, history)
- Offer to help install
- Provide installation instructions for their OS

### 2. Connectors

**This section is auto-generated by `/create-agent`** based on the workflow's data source requirements.

`/setup` **verifies** connectors; it can't install them. Connectors belong to the
person's account, not the project, so each person adds their own once. Use
`ListMcpResourcesTool` to check:

1. Call `ListMcpResourcesTool()` without parameters to list what's connected
2. For each connector the workflow needs:
   - Check it appears in the results
   - Verify it's responding (resources returned = working)
   - Report status, and how to add it if missing

**IMPORTANT**: If a connector is missing, give directions but never block:
- Send them to the UI: **Claude Desktop → Settings → Connectors** (pick from the
  list and sign in, or "Add custom connector" with the vendor's remote MCP URL), or
  `/mcp` in Claude Code
- Don't quote package names or point at config files (see
  `.claude/knowledge/connectors.md` for why)
- Mention the plan requirement and the Team/Enterprise admin path when relevant –
  it may be a request to their admin rather than something they can fix
- **Say what the manual alternative is** if the workflow has one, so a missing
  connector never stops them working

**Example**:
```
Checking connectors...
✅ notion - connected (12 resources available)
❌ google-drive - not connected

   Add it: Claude Desktop → Settings → Connectors, find it and sign in.
   (Or /mcp in Claude Code.)

   Not blocking: this workflow also accepts the file pasted in directly.
```

### 3. File Structure

Verify expected directories exist:
- `.claude/commands/`
- `.claude/skills/` or `.claude/agents/`
- `.claude/knowledge/`
- `project-plan/`
- Session directories

### 4. Security Check

Invoke `security-checker` skill to scan for:
- Hardcoded secrets
- Missing .gitignore patterns
- Sensitive files in git

### 5. Environment Variables

If project uses .env:
- Check .env.example exists
- Check .env exists (don't read contents)
- Verify required variables documented

### Report

Show comprehensive status:
```
🔧 Environment Setup Status

Git: ✅ version 2.39.0
Connectors: ⚠️  2/3 connected (google-drive missing)
Files: ✅ All directories present
Security: ✅ No issues found
Environment: ✅ .env configured

Action needed:
- Add the google-drive connector (see above), or use the manual alternative

Once complete, run your workflow: /[workflow-name]
```

## User Experience

This is a diagnostic command that helps troubleshoot setup issues. Be helpful and specific about how to fix problems.
